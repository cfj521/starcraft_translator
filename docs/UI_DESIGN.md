# 界面设计说明 — SC:R 实时翻译软件

> 配合 [PRD.md](PRD.md)、[TECH_DESIGN.md](TECH_DESIGN.md) 阅读。本文定义各界面的结构、字段与交互。
> 下方为 ASCII 线框（mockup），实现用 WPF；尺寸/配色后续在样式阶段细化。

## 1. 界面总览

软件由四类界面组成：

| 界面 | 形态 | 作用 |
|------|------|------|
| **悬浮层 Overlay** | 透明置顶 / 点击穿透 | 在游戏上显示译文（运行时主界面，无边框、不可交互） |
| **托盘菜单 Tray** | 系统托盘右键菜单 | 快速开关、打开配置、校准、退出 |
| **配置窗口 Settings** | 普通窗口（多标签页） | 所有设置项：翻译/OCR/区域/热键/外观/常规 |
| **校准窗口 Calibration** | 全屏半透明可交互覆盖 | 拖框定义 ROI、命名、选类型/列 |

主程序常驻托盘，不占任务栏主窗口；配置窗口按需打开。

### 3.2 翻译 Translation  ★（含"翻译玩家 ID"）
> 实现对齐（Phase 2–4）：**无"快引擎/LLM 三模式"与 Papago/Claude**。实际 = 主引擎单选（DashScope / ChatGPT 订阅）**单活跃、单级**；密钥/登录走 `SecretStore`(DPAPI) 与 OAuth，不进 `settings.json`。

```
引擎（单活跃，托盘可快速切换）
  主引擎          (•) DashScope（阿里云）  ( ) ChatGPT（订阅）
                  [ 设置阿里 Key… ]        [ 登录 ChatGPT… ]
  模型            DashScope [ qwen-flash ]   ChatGPT [ gpt-5 ]

内容范围                                              ┌── 热键可绑
  [✓] 翻译聊天
  [✓] 翻译房间名
  [✓] 翻译地图信息
  [ ] 翻译玩家 ID            (默认关闭)         (F7) ┘
        ⓘ 玩家 ID 多为专有名词，通常不翻译。开启后"房间名列表"
          里的 ID 列也会被翻译。可用热键 F7 随时切换。

质量与省流
  [✓] 启用术语表 (星际黑话)        [ 编辑术语表… ]   ← 命中直出，无网络（始终启用）
  [✓] 启用翻译缓存                 ← 进程内 LRU，容量固定，无 TTL；只存最终态（始终启用）
  [ ] LLM 节流/合并(防刷屏)        ← 后续
  [ ] 保留上下文供 LLM 参考        ← 后续
```

> **"翻译玩家 ID"** 落地为配置项 `Translation.TranslatePlayerId`（默认 `false`）。
> RoomList 型 ROI 的 ID 列是否翻译，取此开关；房间名/地图列始终按各自勾选项翻译。

### 3.3 OCR
> 实现对齐：OCR **仅 PaddleOCR**（RapidOcrNet + 韩文 mobile ONNX 模型随包分发），已取代 Windows 内置 OCR 方案，**无需系统语言包**，识别语言固定韩文。

```
引擎            PaddleOCR（当前唯一实现；内置 OCR 方案已废弃）
识别语言        韩文 (ko)（固定，无需语言包检查）
轮询节拍
  场景检测      每 [ 200 ] ms 识别一次（只比几块静态区，很便宜）
  翻译          每 [ 500 ] ms 跑一轮 OCR+翻译
```
> 注：两个节拍**正交**、改后即时生效（各自钳制 100–5000ms）。捕获侧帧节流自动取两者较快值（`PollInterval.CaptureFloor`）——否则识别配 200ms 也会被翻译的 500ms 上游拖平。原"聊天区/其它区域"两值设计已废弃：其他界面根本不翻译，给它配一个翻译节拍属于假旋钮。原"图像预处理/变化检测灵敏度"控件为占位假设置——RapidOcrNet 不暴露对应旋钮、变化检测为精确文本比对；实测原生分辨率裁条放大 2x 无收益（avgConf .987 直读 vs .982 放大），已整体移除（UI_DESIGN 与 settings.json 字段同步删除，旧文件多余字段读取时自动忽略）。

### 3.4 区域 ROI

数据有两个来源：**用户校准的 ROI**（`rois.json`）与**出厂布局预设**（`layout-presets.json`，被
`%APPDATA%\ScrTranslator\layout-overrides.json` 覆盖）。两类条目同表展示、同表可编辑。

```

┌──────────┬──────────┬────────────────────┬──────────┬───────────┬───────────┐
│ 场景      │ 分辨率    │ 名称                │ 类型      │ 左上角 X,Y │ 宽 × 高    │
├──────────┼──────────┼────────────────────┼─────────────────────┼───────────┤
│ 寻找房间  │3840x2160 │ browsing·聊天(预设)  │ 聊天      │560, 1480  │1600 × 494 │
│ 寻找房间  │3840x2160 │ browsing·房间列表(预设)│ 房间名列表 │708, 610   │1370 × 764 │
│ 房间内    │3840x2160 │ room·聊天(预设)      │ 聊天      │540, 1488  │1610 × 482 │
│ 游戏内    │3840x2160 │ ingame·聊天(预设)    │ 聊天      │ 16, 470   │2296 × 830 │
│ 寻找房间  │3840x2160 │ 房间聊天             │ 聊天      │559, 1481  │1601 × 493 │
└──────────┴──────────┴────────────────────┴──────────┴───────────┴───────────┘
   ↑ 双击任意行 = 编辑；只显示主显示器当前分辨率的行（别的分辨率不进表，避免照着错的改）

房间列表列区域：                            [ 编辑选中 ] [ 删除选中 ]
┌──────────┬───────────┬───────────┐
│ 列名      │ 左上角 X,Y │ 宽 × 高    │
├──────────┼───────────┼───────────┤
│ 房间名(预设)│ 864, 610  │ 552 × 764  │
```

> 三条口径：① **坐标一律整数像素**（该分辨率下）——相对百分比用户读不动，也不便和截图对照；
> ② 只显示主显示器当前分辨率；③ 预设行可编辑，但写的是**覆盖层**，出厂文件永不改写
> （删掉 `layout-overrides.json` 即恢复出厂值）。预设行点"删除"会被明确拒绝并说明原因——
> 它不在 `rois.json` 里，"删"等于改出厂数据。
> "ID 列是否翻译"仍联动 3.2 的"翻译玩家 ID"开关，不在此单独配置。

## 4. 热键设计 Hotkeys

全局热键（`RegisterHotKey`），游戏内也生效。默认绑定：

| 功能 | 默认热键 | 说明 |
|------|----------|------|
| 开/关 翻译 | `F9` | 总开关，等于托盘"翻译" |
| 显/隐 悬浮层 | `F10` | 临时隐藏译文看原画面 |
| 进入校准 | `F8` | 切到校准窗口框选区域 |
| 打开配置 | `Ctrl+F9` | 打开配置窗口 |
| **切换"翻译玩家 ID"** | `F7` | 直接开关 ID 翻译，无需进配置 |
| 暂停/继续 | `F11` | 暂停捕获与翻译（省资源） |
| 切换 DEBUG 面板 | `F6` | 左上角显示/隐藏诊断面板（场景识别/帧/ROI/翻译状态） |
| 复制诊断信息 | `Ctrl+F6` | 把面板同源的诊断快照拷到剪贴板（面板纯展示、永久点击穿透，不抢焦点） |

规则：
- 热键可在 **3.5 热键** 页自定义；录制式绑定，检测冲突。
- 与游戏自身快捷键尽量错开（SC:R 常用 F1–F4 编队，故默认用 F7–F11）。
- 切换类热键触发后，托盘图标/悬浮层给短暂提示（如 "玩家ID翻译: 开"）。

## 5. 校准窗口 Calibration

### 5.0 进入前置（F8）

校准窗是**半透明覆盖层**，且要靠抓屏做场景检测 —— 看不见游戏画面时框出来的东西全是凭空的。
所以 `App.xaml.cs OpenCalibration()` 先挡一道，任一不满足就托盘气泡说明原因、**不进校准**：

| 情况 | 提示 |
|------|------|
| 找不到目标进程窗口 | "未找到游戏窗口（进程 StarCraft）。请先启动 SC:R（窗口化/无边框）。" |
| 游戏已最小化 | "游戏处于最小化状态，请先还原窗口再按 F8。" |
| 游戏不是前台窗口 | "游戏不在前台，校准会看不清要对齐的画面。请点一下游戏窗口再按 F8。" |

### 5.1 场景自己检测，不依赖 F9

打开时校准窗抓一块游戏窗口区域的屏幕像素（`Graphics.CopyFromScreen`），交给
`SceneRecognizer` 做图像指纹识别 —— **和翻译开关无关**：没按 F9 也能定准当前场景，
于是框出来的区域一定落到对的场景桶里（而不是全塞进"寻找房间"）。
检测失败才退回打开方传进来的场景值，并记日志。

顶部提示常驻显示 `场景【游戏内】 · 分辨率 3840x2160 · 拖动鼠标框选 (Esc 退出 / Enter 保存)`。

### 5.2 预设参考框

当前场景/分辨率的布局预设会画成**只读参考框**（蓝色虚线 + 标签：`聊天(预设)`、`房间列表(预设)`、
`列·房间名`），不吃鼠标也不写盘。目的是让人一眼看见"这块系统已经知道了"，不必重复框。

```
┌──────────────── 校准模式 (Esc 退出 / Enter 保存) ─────────────────────────┐
│ 场景【寻找房间】 · 分辨率 3840x2160 · 拖动鼠标框选                          │
│ ╔═══════════════════════════════════╗                                     │
│ ║ 房间列表(预设)  ← 蓝虚线，只读参考  ║  ┌───────────────┐                  │
│ ║  ┌列·房间名┐ ┌列·地图┐            ║  │ 聊天(预设)     ║                  │
│ ╚═══════════════════════════════════╝  └───────────────┘                  │
│                                                                           │
│  ┌ 名称[ 新区域  ] 类型[ 聊天 ▼ ]              [确定] [取消] ┐              │
│  │ 坐标 (712, 604)  尺寸 1360 × 780  场景【寻找房间】 分辨率 3840×2160 │      │
│  └───────────────────────────────────────────────────────────┘            │
│     ↑ 第二行显示这次框的像素坐标/尺寸/场景/分辨率；按住空白处可拖走            │
└───────────────────────────────────────────────────────────────────────────┘
```

### 5.3 交互细则

- **单击不误弹**：新建框最小边按 **20 物理像素** 判定（不是 DIP —— 高 DPI 下 DIP 会把门槛放大），
  小于它一律当误触，不弹操作条也不留半个框，并记一条 DEBUG 日志。
- **操作条不溢出**：先 `Measure` 自身尺寸，右侧放不下就翻到框的左侧，最后夹进画布范围内。
- **操作条可拖拽**：按住它的空白处（输入框/下拉/按钮除外）即可挪走，免得压住正要对齐的区域。
- RoomList 类型额外可用竖线划列，每列贴语义标签（房间名 / 地图 / 玩家ID / 其它）；
  **翻不翻由「翻译」页的四个开关按语义决定**，不在这里逐列设"翻译/不翻译"。未命中任何列的行一律不翻（最安全）。
- 当前分辨率作为配置 key，换分辨率提示重新校准。
- 保存写入 `rois.json`（见 TECH_DESIGN 3.2），并回调 `probe.ReloadRois()` 让运行中的探测立即生效。

## 6. 配置数据模型（与界面对应，实现对齐版）

> 与代码一致：`src/ScrTranslator.Core/Settings/AppSettings.cs` + `Translation/TranslationSettings.cs` + `Roi/RoiModels.cs`。
> **实际字段**（非早期设想）：无 `EngineMode(FastOnly/Hybrid/LlmOnly)`，也无两级开关——`Active` 单选、单级；密钥字段**不在** `AppSettings` 内（走 `SecretStore`/DPAPI）。

```csharp
class AppSettings {
    GeneralSettings General;      // TargetProcess / AutoStart / StartMinimized / AutoTranslateOnLaunch
    TranslationSettings Translation;
    OcrSettings Ocr;              // SceneDetectPollMs=200 / TranslatePollMs=500（两个正交节拍；旧 ChatPollMs/OtherPollMs 与预处理/灵敏度字段均已移除，见 §3.3 注）
    AppearanceSettings Appearance;// FontFamily / FontSize / Opacity / BackplateOpacity(文字底衬 0.8) / ShowOriginalAndTranslation
    Dictionary<string, HotkeyBinding> Hotkeys;  // 功能名 → (Modifiers, Vk)，默认 F7–F11/Ctrl+F9
    // ROI 配置单独存 rois.json（RoiStore），按 场景 → 分辨率 bucket 分组，RoomList 可含列定义
// 界面布局预设另有两层：出厂 layout-presets.json（exe 旁，只读，量测产物）
//   + 覆盖层 %APPDATA%\ScrTranslator\layout-overrides.json（配置页改预设时落这里）
//   同 (场景,分辨率) 覆盖胜出；删覆盖层文件即恢复出厂值。场景识别参考同理
//   （scene-refs.json + scene-overrides.json），见 TECH_DESIGN 3.9
}

class TranslationSettings {
    TranslationEngine Active;     // DashScope | ChatGpt（单活跃）
    string DashScopeModel;        // 默认 qwen-flash
    string ChatGptModel;          // 默认 gpt-5
    int TimeoutSeconds;           // 整轮(快+质量共用)超时，默认 10

    bool TranslateChat   = true;
    bool TranslateRoomName = true;
    bool TranslateMapInfo  = true;
    bool TranslatePlayerId = false;  // ★ 对应"翻译玩家ID"开关 / F7
}
```

> 实现：`TranslationScope.ShouldTranslate` 决定某条文本是否翻译，依据 = ROI 类型对应的开关；
> RoomList 的列先由 `HitColumn`（按该行在框内的水平位置）定语义，ID 列取 `TranslatePlayerId`。
> 另有一道**内容闸门** `KoreanText.ContainsHangul`：整行不含谚文（地图名、`Top vs Bottom`、表头…）
> 直接不进翻译管线 —— 提示词要求"纯英文原样保留"，送过去只会拿回同样的英文，白花请求还显示成噪声。
> API Key / OAuth token 持久化前用 DPAPI 加密（`SecretStore`，与 `settings.json` 分离）。
